# 競合見出し分析・最適化スキル

競合記事の見出し構造を取得・比較分析し、SEOに強い最適な見出し案を生成する。

## バンドルファイル構成

```
heading-optimizer/
├── SKILL.md                       ← このファイル
└── scripts/
    └── parse_headings.py          ← 見出し抽出・分析スクリプト
```

---

## 📥 入力情報

**必須:**
1. **ターゲットキーワード** — 対策したい検索キーワード
2. **競合URL** — 分析対象の記事URL（1〜5件）

**オプション:**
- **記事の目的** — 情報提供 / 比較 / ハウツー / まとめ など
- **目標文字数** — 執筆予定の記事のボリューム感

---

## 🔧 実行ステップ

### ステップ1: 競合記事の見出し取得

WebFetchツールで各URLのHTMLを取得し、`parse_headings.py` を使って見出しタグ（H1〜H3）を抽出する。
スクリプトが使えない場合は、取得したHTMLから `<h1>`, `<h2>`, `<h3>` タグを直接パースする。

取得した見出しを以下の形式で整理する：

```
【競合A】URL: https://example.com/article
  H1: タイトルテキスト
  H2: セクション1
    H3: サブセクション1-1
    H3: サブセクション1-2
  H2: セクション2
  ...
```

### ステップ2: 見出し構造の分析

取得した複数の競合記事を横断的に分析し、以下を抽出する：

**共通パターンの特定:**
- 複数の競合に共通して登場する見出しキーワード → **必須トピック**
- 1〜2件にしか登場しない見出し → **差別化ポイント候補**
- 見出しの数（H2の平均個数、H3の使用率）

**キーワード出現分析:**
- 各見出しにおけるターゲットキーワードの使われ方
- 共起するキーワード（LSI候補）
- ユーザーの検索意図を示すフレーズ（「方法」「比較」「おすすめ」など）

**構成タイプの分類:**
| タイプ | 特徴 |
|--------|------|
| 解説型 | 「〇〇とは」「基礎知識」から始まる |
| ステップ型 | 「手順1」「ステップ」が並ぶ |
| 比較型 | 「〇〇と△△の違い」「メリット・デメリット」 |
| まとめ型 | 複数の選択肢を羅列 |

### ステップ3: 最適見出し案の生成

分析結果をもとに、以下の基準で最適な見出し構成を2〜3パターン提案する。

**SEO見出し設計の原則:**
- **H1**: ターゲットキーワードを自然に含む（記事タイトルと一致）
- **H2**: 競合共通トピック（必須）＋差別化トピック（1〜2個）を配置
  - キーワードバリエーションや疑問形（「〜するには？」）を活用
  - 読者の検索意図に沿った順序で並べる
- **H3**: 各H2の内容を具体化・細分化
  - LSIキーワードや具体例を含める
  - H2の内容を3〜5個のH3で網羅する

**提案フォーマット（1パターンにつき）:**

```markdown
### パターンA: [パターン名・特徴]

**H1:** [タイトル]

**H2:** [セクション1]
  - H3: [サブセクション1-1]
  - H3: [サブセクション1-2]

**H2:** [セクション2]
  - H3: [サブセクション2-1]

**H2:** [セクション3]
  - H3: [サブセクション3-1]

**H2:** まとめ

---
**選定理由:**
- 競合A・Bで共通していた〇〇トピックを網羅
- 競合が扱っていない〇〇を差別化ポイントとして追加
- ユーザーの検索意図「〜したい」に沿った順序で構成
```

### ステップ4: 競合比較レポートの出力

最終出力として以下のレポートを生成する：

```markdown
## 競合見出し分析レポート

### 対象キーワード
[ターゲットキーワード]

### 競合記事の見出し一覧
[ステップ1で整理した各URLの見出し構造]

### 分析サマリー
- 必須トピック: [共通して登場するH2テーマ一覧]
- 差別化ポイント候補: [独自性を出せるテーマ]
- 平均H2数: X個 / 平均H3数: X個
- 主な構成タイプ: [解説型 / ステップ型 / 比較型 / まとめ型]

### 最適見出し案

[パターンA〜Cの提案]

### 推奨パターンと理由
[最もSEO効果が期待できるパターンとその根拠]
```

---

## ⚠️ 注意事項

- URLが取得できない場合（認証・JavaScript依存など）はその旨をユーザーに伝え、スキップして他のURLで進める
- 競合URLが1件しかない場合は分析パターンを省略し、直接最適化案の生成へ進む
- 見出し案はあくまで「提案」であり、最終判断はユーザーに委ねること
- 著作権に配慮し、見出しテキストを丸ごとコピーせず、構造・意図のみを参考にする
